# BIMASATU (Bimas Islam Kabupaten Indramayu): panduan untuk AI (baca ini dulu)

Dokumen ini dibuat agar AI (atau developer baru) cepat paham proyek ini tanpa membaca seluruh kode. Urutan baca yang disarankan:
`README.md` (ini) -> `bop.sql` (data BOP + aturan) -> `supabase/functions/bop/index.ts` (server Supabase) -> `apps-script/Code.gs` (server Apps Script) -> `js/core.js` lalu berkas menu di `js/` -> `PANDUAN-INSTALASI.md` (pemasangan dari nol).

**Urutan pemasangan:** `bop.sql` (SQL Editor Supabase) -> `bop.mjs akun` -> `bop.mjs drive` -> `supabase/functions/bop/index.ts` (deploy; satu-satunya berkas TypeScript) -> `apps-script/*.gs` + `appsscript.json` -> `js/config.js` dan push ke GitHub Pages. Alasan urutannya ada di PANDUAN-INSTALASI.md bagian 1.
`bop.mjs akun` hanya membuat 1 admin + 31 Operator KUA; akun peran lain (Bendahara BOP, Verifikator BOP, BAST NR, Kemasjidan, PNBP NR) dibuat admin di dalam aplikasi (Pengaturan > Daftar akun).

## 1. Tujuan
Aplikasi web layanan 31 KUA (Kantor Urusan Agama) se-Kabupaten Indramayu dan Seksi Bimas Islam. Modul: **BOP** (Biaya Operasional Perkantoran, inti), **Jaspro Transport**, **BAST NR**,
**Sertifikat Masjid/Musala**, **Sertifikat Arah Kiblat**, manajemen akun (tujuh peran), dan **Hak Akses Menu** (menu mana yang boleh dibuka tiap peran). Satu website, **dua backend**: Supabase (BOP + Jaspro) dan Apps Script + Spreadsheet (Sertifikat + BAST NR), supaya kuota Supabase hemat.
Nama aplikasi **BIMASATU** dipakai di tiga tempat yang **harus sama**: `CFG.nama` di `js/config.js`, `APP_NAME` di `supabase/functions/bop/index.ts`, dan `APP_NAME` di `bop.mjs` (nama folder master di Google Drive).

Alur BOP: admin menetapkan **Anggaran** tahunan per KUA -> operator KUA menyusun **RPD** (rencana penarikan dana) per bulan ->
operator mengisi **Realisasi** per bulan + unggah **LPJ** -> admin atau verifikator **memverifikasi** (status Dibayar wajib mencatat **nominal yang dibayarkan**) -> **Laporan** Excel/PDF.
Pembayaran lewat SAKTI (autopayment) hanya **Listrik dan Telepon/Internet**. Pengaturannya **global**: satu ceklis per KUA + POS di **Pengaturan SAKTI** (tanpa bulan/tahun berlaku).
POS yang dicentang tidak diisi operator: nominalnya diinput admin (atau Bendahara BOP) tiap bulan di **Realisasi SAKTI** dan dijumlahkan dengan Realisasi manual. Air adalah POS manual biasa.
**Realisasi SAKTI tidak dibatasi RPD**: uangnya sudah dibayar sistem keuangan, jadi harus tetap dapat dicatat walau melebihi RPD. Akibatnya ada di sisi Operator KUA:
selama Realisasi sebuah POS (manual + SAKTI) melebihi RPD setahun, atau Realisasi sebuah bulan melebihi RPD bulan itu, operator tidak dapat mengirim Realisasi (tombol Kirim nonaktif, kelebihannya ditampilkan; server menolak juga) sampai admin menyesuaikan RPD.
Data dari sistem lama (Spreadsheet/Apps Script) dapat dibawa lewat menu **Impor Data Lama**, termasuk menyalin berkas LPJ ke struktur Google Drive baru.

**Peran** (tujuh; kolom `profiles.role`): `admin` · `operator` (Operator KUA, terikat satu KUA) · `bendahara_bop` · `verifikator_bop` · `bast_nr` · `kemasjidan` · `pnbp_nr`.
Admin selalu boleh semua menu dan satu-satunya yang mengatur **Hak Akses Menu**, membuat/mengubah akun, dan mereset password peran mana pun. Menu yang boleh dibuka peran lain diatur admin (tabel `hak_akses`);
isi awal: Operator KUA = BOP, RPD, Realisasi, Laporan · Bendahara BOP = BOP, RPD, Verifikasi, Realisasi SAKTI, Laporan · Verifikator BOP = BOP, RPD, Verifikasi, Laporan · BAST NR = semua menu BAST NR · Kemasjidan = semua menu Sertifikat · PNBP NR = Jaspro Transport.
Hak itu ditegakkan **server** (RLS/trigger lewat `can_menu()`, Apps Script, Edge Function); tampilan hanya menyembunyikan menu. Rincian di bagian 6.

## 3. Arsitektur
```
Browser (index.html @ GitHub Pages; js/*.js dimuat berurutan)
  |-- supabase-js (kunci publishable) --> PostgREST + Auth (Supabase)    <- BOP + Jaspro; dijaga RLS + trigger
  |-- fetch /functions/v1/bop?action=... (Bearer token login) --> Edge Function bop
  |                                                         |-- Supabase (service role, di server): akun, profil, hak_akses
  |                                                         |-- Google Drive API (LPJ BOP dan arsip BAST NR, SATU folder master; refresh token di Secrets)
  |-- fetch Web App Apps Script (POST text/plain, JSON + token login Supabase)  --> Apps Script (aksi dibatasi menu peran)
  |                                                         |-- memeriksa token + menu ke Supabase (RPC akses_saya, di-cache 5 menit)
  |                                                         |-- Spreadsheet: DataMasjid, DataKiblat, Pengaturan, BastPegawai, BastBA, BastSetting
  |                                                         |-- Google Drive API: hanya MEMBACA/membuang arsip BAST NR LAMA (belum di folder master), sampai dipindah
  |-- fetch Web App Apps Script LAMA (hanya menu Impor Data Lama BOP, hanya membaca)
Cloudflare Turnstile: captcha login (Site Key di js/config.js; Secret Key di pengaturan Auth Supabase)
```
Prinsip: **rahasia hanya di server** (Supabase Secrets / `.env` lokal / Apps Script). Browser hanya memegang URL, publishable key, Site Key, dan URL Web App.
**Aturan bisnis BOP ditegakkan di database (trigger SECURITY DEFINER)**; **aturan BAST NR ditegakkan di `apps-script/Bast.gs`** di bawah kunci skrip. UI hanya meniru agar pesannya cepat dan jelas.
**Login hanya satu** (Supabase). Apps Script tidak punya login sendiri: ia menerima token login Supabase, menanyakan peran dan daftar menu akun itu (RPC `akses_saya`), lalu hanya menjalankan aksi yang menunya dimiliki akun tersebut (Admin: semua).
**Hak akses menu dibaca tiga penegak**: database (`can_menu()` pada RLS/trigger), Apps Script (kunci `menu:` pada tiap aksi), dan Edge Function (tabel `profiles` + `hak_akses`). Tampilan (sidebar, `route()`) hanya mengikuti.

**Login memakai username**, bukan email. Supabase Auth tetap membutuhkan email, jadi akun disimpan sebagai `<username>@<EMAIL_DOMAIN>`; pengguna tidak pernah mengetik domainnya
(`toEmail()` di `js/core.js` menambahkannya dari `CFG.domain`; email penuh yang diketik tetap diterima apa adanya). Operator: `kua_<kecamatan huruf kecil tanpa spasi>`, mis. `kua_anjatan`,
`kua_indramayu`, `kua_kedokanbunder`. `CFG.domain` (`js/config.js`) dan `EMAIL_DOMAIN` (`.env` untuk `bop.mjs`) harus sama.
**Keamanan wajib:** pendaftaran mandiri Supabase harus **dimatikan** (Authentication > Allow new users to sign up = off). Trigger `handle_new_user` memercayai `role` di metadata akun (tujuh peran dikenal; yang lain dianggap `operator`), jadi bila pendaftaran terbuka siapa pun yang tahu URL dan publishable key dapat mendaftarkan dirinya sebagai admin atau peran apa pun. Akun dibuat admin lewat aplikasi (Edge `buat-akun`) atau `bop.mjs`.

## 4. Model data (lihat `bop.sql`)
| Tabel | Kunci/kolom penting |
|---|---|
| `profiles` | `id` (=auth.users.id), `nama`, `kua` (teks), `kua_id`, `role` (`admin`, `operator`, `bendahara_bop`, `verifikator_bop`, `bast_nr`, `kemasjidan`, `pnbp_nr`; hanya `operator` yang punya KUA). Dibuat otomatis oleh trigger `handle_new_user` dari `user_metadata`. Klien tidak bisa menulis (peran diubah Edge `ubah-akun`). Username tidak disimpan: ia bagian email sebelum `@` (admin membacanya lewat RPC `akun_daftar()`). Admin terakhir tidak dapat diturunkan (`profiles_admin_guard`). |
| `hak_akses` | `(role, menu)` kunci utama: satu baris = satu peran boleh membuka satu menu (+ `updated_by/at`). Admin tidak disimpan (selalu semua menu). Dibaca semua akun login (bukan rahasia); ditulis hanya lewat RPC `set_hak_akses(p_data)` (satu transaksi, hanya admin; menolak menu tak dikenal dan pemberian yang dilarang, lihat bagian 6). Diisi bawaan **sekali** (`config.hak_akses_awal`), jadi menjalankan ulang `bop.sql` tidak mengembalikan menu yang sudah dicabut admin. |
| `kua` | 31 baris. `nama_kua` berpola `KUA Kec. <Kecamatan>`; `kecamatan` dipakai untuk username dan nama folder Drive. |
| `pos` | 11 baris = 11 **unit input**: rincian bila ada (ATK Kantor, Jamuan Tamu, Pramubakti, Alat Rumah Tangga, Penggandaan/Penjilidan, Spanduk) atau kode POS itu sendiri (522111 Listrik, 522112 Telepon/Internet, 522113 Air, 523111 Pemeliharaan Gedung, 523121 Pemeliharaan Peralatan). `kode_pos` = **kode akun**, selalu ditampilkan di UI. |
| `config` | Pasangan `key`/`value` (jsonb): `rpd_enabled`, `realisasi_enabled`, `max_file_size_mb`, `max_file_count`, `bulan_edit_rpd` (array bulan). LPJ selalu wajib (tidak ada kunci untuk itu). |
| `anggaran` | **1 baris = 1 tahun**: `tahun` (kunci utama), `items` jsonb `{"<kua.id>": nominal}`, `total` (dihitung trigger). Operator tidak membaca tabel ini (satu baris memuat semua KUA): operator memanggil RPC `anggaran_tahun(tahun)` (hanya KUA-nya), admin menulis lewat RPC `set_anggaran(tahun, items)` yang **menggabungkan** hanya KUA yang dikirim (nilai 0 = hapus). |
| `rpd` | **1 record = 1 KUA x 1 bulan**: `(kua_id, tahun, bulan)` unik, `items` jsonb, `total`. |
| `realisasi` | **1 record = 1 KUA x 1 bulan**: sama seperti RPD + `status`, `file_lpj_url`, `catatan_admin`, `submitted_*`, `verified_*`, `paid_at`, `nominal_dibayar` (nominal yang dibayarkan admin; terisi hanya saat status `paid`). |
| `metode_pembayaran` | **Ceklis global** per KUA + POS: `(kua_id, pos_id)` kunci utama, `metode` (`MANUAL`/`SAKTI`), `updated_by/at`. Hanya POS 522111/522112. Belum ada baris = MANUAL. |
| `realisasi_sakti` | **1 record = 1 KUA x 1 POS x 1 bulan** (unik): hanya `nominal` (+ `updated_by/at`). Tanpa status, tanggal, sumber, atau keterangan. Hanya pemegang menu `sakti` yang menulis (Admin; bawaan juga Bendahara BOP). |

Fungsi yang dipanggil klien (RPC): `anggaran_tahun`, `set_anggaran`, `akun_daftar` (admin; peran lain mendapat 0 baris), `impor_baris` (admin), `akses_saya` (profil + daftar menu akun yang login; dipakai tampilan dan Apps Script), `set_hak_akses` (admin).
Fungsi bantu di database: `menu_keys()` (daftar kunci menu), `can_menu(menu)` (admin: selalu; lainnya: ada barisnya di `hak_akses`), `bop_baca_semua()` (boleh membaca BOP semua KUA: admin, atau peran non-operator yang punya salah satu menu anggaran/rpd/verifikasi/metode/sakti/laporan), `peran_label(role)`.
Semuanya `SECURITY DEFINER` dengan `execute` dicabut dari `anon`.

Bentuk `items`: `{"<pos.id>": nominal}`, kunci = id POS sebagai string, nilai bilangan bulat rupiah > 0 (nol dibuang). Contoh:
`{"1": 1500000, "7": 300000}`. `total` dihitung trigger (`items_total`), jangan diisi manual.
Semua uang = bilangan bulat rupiah (bigint), tanpa desimal, **maksimal 10 digit (Rp 9.999.999.999)** per isian (`nominal_max()` di SQL, `MAXD` di JS). Bulan = 1..12.

**Pembayaran SAKTI.** `metode_pos(kua, pos)` (SQL) / `metodeOf(vers, kid, pid)` (JS): baris ada -> nilainya, tidak ada -> MANUAL. Jumlah SAKTI sebulan/setahun (`sakti_items`/`sakti_year`, JS `saktiOf`/`saktiYear`)
dijumlahkan dengan Realisasi manual pada validasi dan laporan. Satu bulan hanya boleh punya **satu sumber per POS**: Realisasi SAKTI ditolak bila Realisasi manual bulan itu sudah memuat POS yang sama.
Karena pengaturan global, Realisasi manual lama (sebelum POS dicentang) tidak dihapus: operator tidak bisa mengisi/mengubahnya, tetapi nilai lamanya **dipertahankan** server saat Realisasi yang ditolak diperbaiki.
Tidak ada DELETE untuk siapa pun (koreksi: kosongkan nominal = Rp 0). `updated_by` diisi server.

## 6. Hak akses
**Model.** Satu akun = satu peran. **Admin** selalu boleh semua menu (kecuali `realisasi`: mengisi Realisasi KUA sendiri khusus Operator KUA). Peran lain hanya boleh menu yang tercentang untuknya di halaman **Hak Akses Menu** (khusus admin; tabel `hak_akses`).
Menu **Pengaturan** (ganti password sendiri) terbuka untuk semua akun. Kunci menu (`menu_keys()` di `bop.sql`, `MENU_DEF` di `js/akses.js`, atribut `data-menu` di `index.html`, dan hash halaman):
`bop` `anggaran` `rpd` `realisasi` `verifikasi` `metode` `sakti` `config` `impor` `laporan` · `bast` `bast-buat` `bast-pegawai` `bast-setting` · `sert-masjid` `sert-kiblat` `sert-pengaturan` · `jaspro` · `akses`.
**Aturan pemberian** (dijaga `set_hak_akses()` di database dan `aksesBoleh()` di tampilan): `akses` dan `impor` khusus Admin; Operator KUA tidak dapat diberi `anggaran`, `verifikasi`, `metode`, `sakti`, `config` (ia hanya boleh melihat data KUA-nya sendiri); `realisasi` hanya untuk Operator KUA.

| Hal | Admin | Peran lain (menurut menu yang diberikan; bawaan di kurung) |
|---|---|---|
| Anggaran | tulis semua KUA (RPC `set_anggaran`) | menu `anggaran` (tidak ada bawaan); Operator KUA membaca KUA-nya (RPC `anggaran_tahun`) |
| RPD | tulis/baca semua KUA | Operator KUA (`rpd`) menulis RPD KUA-nya pada bulan yang dibuka; Bendahara dan Verifikator BOP (`rpd`) **hanya membaca** semua KUA |
| Realisasi | baca semua | Operator KUA (`realisasi`) membuat/memperbaiki KUA-nya (aturan 9); pemegang `verifikasi` (Bendahara, Verifikator) mengubah **status** dan nominal dibayar saja |
| Pengaturan SAKTI, Realisasi SAKTI, Config | tulis | menu `metode`, `sakti` (Bendahara BOP), `config`; Operator KUA membaca pengaturan dan Realisasi SAKTI KUA-nya |
| Laporan | semua KUA | menu `laporan`: Operator KUA = KUA-nya, peran lain = semua KUA |
| Impor Data Lama, Hak Akses Menu | ya | tidak dapat diberikan |
| Jaspro Transport | ya (RLS `jaspro_menu`) | menu `jaspro` (PNBP NR) |
| BAST NR | ya | menu `bast` (Riwayat dan arsip), `bast-buat`, `bast-pegawai`, `bast-setting` (BAST NR) |
| Sertifikat | ya | menu `sert-masjid`, `sert-kiblat`, `sert-pengaturan` (Kemasjidan); data Sertifikat hanya diminta untuk menu yang dimiliki |
| Akun | buat akun, ubah nama/peran/KUA, **reset password peran mana pun** (Edge `buat-akun`, `ubah-akun`, `reset-password`) | ganti password sendiri (Pengaturan) |

**Tiga lapis penjagaan.** (1) Tampilan: `applyMenus()` menyembunyikan menu yang tidak dimiliki dan `route()` mengalihkan alamat yang menunya tidak dimiliki ke halaman awal peran (`homeMenu()`). (2) Server: RLS/trigger memakai `can_menu()`; Apps Script menolak aksi yang menunya tidak dimiliki dengan `FORBIDDEN`; Edge Function memeriksa peran dan menu dari tabel (bukan kiriman klien).
(3) Perubahan hak akses berlaku di tampilan saat halaman dimuat ulang atau login ulang, dan di Apps Script paling lama 5 menit (cache pemeriksaan login).

## 7. Frontend (`index.html` + `js/` + `views/` + `css/`)
**Cara kerja berkas.** Semuanya skrip klasik (bukan ES module) dimuat berurutan oleh `index.html`: `config` -> `core` -> `bop` -> `akun` -> `jaspro` -> `bast` -> `sertifikat` -> `app`. Semua berkas berbagi **satu lingkup global**
(`const`/`let`/`function` tingkat atas saling terlihat; nama tidak boleh kembar antarberkas). Aturan pemuatan:
- Kode yang berjalan **saat dimuat** (di luar badan fungsi) hanya boleh memakai nama dari berkas yang dimuat lebih dulu. Karena itu `pages` di `core.js` dimulai kosong (`const pages = {}`) dan **tiap berkas menu mendaftarkan halamannya di akhir berkasnya**: `Object.assign(pages, { ... })`.
- Pernyataan pemicu (event, `onAuthStateChange`, `hashchange`) berada di `app.js` yang dimuat paling akhir. Jangan menambah pemicu semacam itu di berkas lain.
- Pemanggilan antarberkas **di dalam fungsi** bebas (mis. `core.js` memanggil `jpReset`/`bnReset` saat logout), karena saat dijalankan semua berkas sudah termuat.
- Menu **Sertifikat** dimuat malas oleh `sertifikat.js`: pustaka CDN + mesin PDF + `views/*.html` diunduh saat menu pertama dibuka, lalu `sertifikat-masjid.js`, `arah-kiblat.js`, `pengaturan-sertifikat.js` dimuat **berurutan** (berbagi variabel) dan `loadMasjidList/loadKiblatList/loadPengaturan` dipanggil. Kegagalan jaringan dapat diulang tanpa memasang ulang tampilan.
- Pembusukan cache: setiap rilis jalankan `node bump-versi.mjs` (menaikkan `?v=` di `index.html` dan `APP_VERSI` yang dipakai berkas yang dimuat malas).
- Menambah menu baru: buat `js/<menu>.js` (fungsi `pageXxx`, daftarkan lewat `Object.assign(pages, ...)` di akhir berkas), tambahkan `<script>` di `index.html` sebelum `app.js` dan tautan sidebar dengan `data-menu="<kunci>"`. Kunci menu itu harus didaftarkan di empat tempat yang sama: `menu_keys()` di `bop.sql` (dan seed `hak_akses` bawaan bila perlu), `MENU_DEF` di `js/akses.js`, `HOME_ORDER` di `js/core.js` (bila boleh menjadi halaman awal), dan kunci `menu:` pada aksi Apps Script / RLS / Edge Function yang melayaninya. Tidak ada lagi daftar "halaman admin-only" di `route()`: yang menentukan hanya `can(menu)`.

Lokasi fungsi: halaman BOP (`pageRpd`, `pageRealisasi`, `pageVerifikasi`, `pageLaporan`, `pageAnggaran`, `pageMetode`, `pageSakti`, `pageConfig`, `pageImpor`, `legacy*`, `build*`, `multiSelect`) di `js/bop.js`; `pagePengaturan`, `openReset`, `pwPair` di `js/akun.js`;
`JX`, `J`, `jp*`, `pageJaspro` di `js/jaspro.js`; `BX`, `B`, `bn*`, `bb*`, `bp*`, `pageBast*` di `js/bast.js`; sisanya (helper, router, auth, `api`, `gas`, `openViewer`, `loadJs`) di `js/core.js`. Nama fungsi sama dengan versi satu-file.

Peta kode (fungsi tetap bernama sama):
- **Konfigurasi**: `CFG` dan `APP_VERSI` di `js/config.js` (`nama`, `url`, `key`, `turnstile`, `gas`, `domain`). Hanya ini yang perlu diisi per instalasi; `app.js` menampilkan peringatan bila masih berisi nilai contoh.
- **Auth**: login (username) + Turnstile; `toEmail()` menambahkan `@CFG.domain`; "Ingat saya" memakai adapter storage khusus (`localStorage` vs `sessionStorage`, kunci `bop.remember`/`bop.email`, yang disimpan = username); `boot()` memuat profil (`me.username` = bagian email sebelum `@`) dan daftar menu (RPC `akses_saya` -> `me.menus`; `can(menu)`), lalu `route()`. `boot()` punya penjaga `booting`: Supabase dapat mengirim dua peristiwa login hampir bersamaan (INITIAL_SESSION dan SIGNED_IN), dan tanpa penjaga itu profil, hak akses, dan halaman dimuat dua kali.
- **Routing**: hash (`#rpd`, `#realisasi`, ...). `pages` memetakan hash -> fungsi `pageXxx()`. `route()` hanya membuka hash yang menunya dimiliki akun (`can(k)`); selain itu dialihkan ke `homeMenu()` (menu pertama yang dimiliki menurut `HOME_ORDER`, atau `pengaturan`). `pengaturan` selalu boleh. Sidebar: grup **BOP**, **BAST NR**, **Sertifikat** (grup disembunyikan bila semua isinya tersembunyi), lalu **Jaspro Transport**, **Hak Akses Menu**, dan **Pengaturan**; semua tautan bermenu membawa `data-menu`. Database lama tanpa `akses_saya()` memakai daftar menu lama (`MENU_LAMA`: Admin dan Operator KUA) dan admin melihat peringatan `#dbWarn` untuk menjalankan `bop.sql`.
- **Helper**: `$` (getElementById), `esc` (WAJIB untuk teks pengguna di innerHTML), `note(teks, tipe)`, `rp()` (format 1.500.000), `num()`, `fmtIn()` (format saat mengetik, kursor tetap, **dipotong 10 digit**), `yearSel()`, `posLabel()` ("kode · nama"), `isum/sumT`, `ST` (status -> kelas badge + teks), `master()` (cache `kua`/`pos`/`config` di memori, `M`).
- **Server**: `api(query, opt)` memanggil `/functions/v1/bop`. `showDocs()` daftar dokumen (+hapus bila boleh).
- **Penampil dokumen**: `openViewer(files, idx, load, side)` dipakai di **semua menu** (Realisasi, Verifikasi, arsip BAST NR). `load(file)` mengembalikan `Response`; PDF/gambar dikenali dari `Content-Type`. Memakai dialog tersendiri `#vdlg` (dapat dibuka di atas dialog detail BAST). pdf.js; zoom Ctrl+scroll/pinch/tombol/dua kali klik, geser, putar, posisi dijepit; **penunjuk halaman** "Halaman X dari N" = halaman dengan area tampak terbesar, dihitung di ruang dokumen sehingga benar di semua rotasi (`pageInd`). Rancangannya (jangan diubah tanpa menjalankan uji penampil di bagian 11):
  - **Ruang dokumen**: lebar halaman = `W`; tiap halaman = *slot* (ukuran SETELAH diputar, ditaruh di tumpukan) berisi *kotak* (ukuran asli) yang diputar dengan CSS transform. Memutar hanya menyusun ulang slot (`layout()`), tanpa merender ulang halaman. `toBox`/`toSlot` memetakan titik slot <-> kotak. Posisi panggung `#vws`: titik (a, b) tampil di (x + a·s, y + b·s).
  - **Rotasi tidak mengubah tempat dan zoom**: `turn(by)` mencatat titik di tengah layar (halaman k + (u, v)), memutar, lalu menaruh titik yang sama kembali di tengah; zoom `s` tidak disentuh. Dulu putar memanggil "pas layar" untuk tumpukan halaman yang baru, sehingga zoom mengecil dan halaman melompat ke atas. Posisi tetap dijepit (tepi dokumen tidak pernah masuk ke layar), jadi di dekat tepi titik tengah dapat bergeser sedikit.
  - **Batas zoom** (`lim()`) **tidak bergantung rotasi**: atas = `V_ZOOM` (10) kali "pas lebar", dan untuk gambar sedikitnya 3 piksel layar per piksel gambar asli (`NW`); bawah dari tumpukan terlebar/tertinggi di rotasi mana pun. Dulu batas atas dihitung dari tumpukan yang sedang diputar sehingga runtuh setelah memutar PDF. `fit(k)` pas-lebar untuk halaman yang sedang dilihat (bukan selalu halaman pertama).
  - **Teks kecil tetap terbaca**: pdf.js dirender sekali pada resolusi sedang; saat zoom besar, `sharp()` merender **kanvas tajam** (tile) hanya untuk bagian yang tampak ditambah margin 30% (`render({transform})` dengan geseran), setelah jeda 150 ms dan hanya bila `s·dpr` lebih besar dari 1,1 kali resolusi dasar. Batas per kanvas `V_MAXPX` (16 juta piksel) dan `V_MAXSIDE` (8192 px; iOS Safari membatasi sekitar 16,7 juta piksel); kanvas yang tidak lagi dipakai dibuang (`drop`), dan tile lama dipakai ulang bila masih menutupi tampilan.
  - `side` (HTML atau fungsi, opsional) = panel **Rincian Realisasi per POS** di KIRI dokumen sebagai pembanding (`realisasiSide()`): Realisasi operator mengisinya dari **isian form saat ini** (belum tentu tersimpan), Verifikasi dari data tersimpan; **semua POS tampil**, juga yang bernilai 0; POS yang dibayar lewat SAKTI berwarna biru; tombol "Rincian" menyembunyikan/menampilkan (layar sempit: panel menimpa dokumen, tersembunyi awalnya; tombol itu dan tombol "Pas layar" memanggil `fit()`, karena lebar area dokumen berubah). Arsip BAST NR tidak memakai panel.
  - **Semua id di penampil berawalan `vw` dan harus unik di seluruh dokumen**: `getElementById` mengambil elemen PERTAMA di halaman, jadi id yang sama dengan halaman di belakangnya (dulu `vst` = pilihan status di Verifikasi) membuat zoom/geser/ukuran mengenai elemen yang salah (dokumen tidak bergerak dan kotak status membesar setelah penampil ditutup). Penutupan (`vOff`) membuang pendengar, pengamat ukuran, dan kanvas; peristiwa `close` dialog tidak serempak, jadi jangan membuka lagi sebelum selesai.

- **Hak Akses Menu** (`js/akses.js`): matriks peran x menu per kelompok (BOP, BAST NR, Sertifikat, Lainnya); sel yang tidak boleh diberikan berupa ikon terlarang beserta alasannya; peran tanpa menu sama sekali meminta konfirmasi; "Kembalikan ke bawaan" hanya mencentang ulang (tersimpan bila Simpan ditekan); satu simpan = satu panggilan `set_hak_akses` (satu transaksi).
- **Realisasi SAKTI dan Operator KUA** (`js/bop.js`): `pageSakti` menyimpan walau melebihi RPD: baris yang melebihi ditandai kuning dengan peringatan "N KUA melebihi RPD" dan keterangan RPD per kotak, lalu toast peringatan menyebut KUA terkait saat tersimpan. `pageRealisasi` menghitung kelebihan RPD setahun per POS (manual semua bulan + SAKTI) dan per bulan; bila ada, daftar menampilkan banner merah "Realisasi <tahun> sudah melebihi RPD setahun, jadi Realisasi baru belum dapat dikirim" berisi rincian per POS (terpakai manual + SAKTI, RPD setahun, kelebihan), dan detail menonaktifkan tombol Kirim dengan rincian yang sama (kelebihan bulanan juga ditampilkan). Konvensi: teks UI dan komentar berbahasa Indonesia; tanpa `localStorage` untuk data bisnis (kecuali kenyamanan: ingat login, alamat sistem lama); tidak ada log aktivitas; query hanya kolom yang perlu. **Id elemen harus unik di seluruh dokumen** (halaman + dialog + penampil yang terbuka bersamaan); penampil memakai awalan `vw`. Uji pengaman: render setiap rute dan periksa tidak ada id ganda.

## 8. Edge Function (`supabase/functions/bop/index.ts`)
`GET/POST /functions/v1/bop?action=<aksi>` dengan `Authorization: Bearer <token login>`. Dideploy dengan `--no-verify-jwt` karena fungsi memverifikasi
token (`auth.getUser`), peran (tabel `profiles`), dan menu (tabel `hak_akses`, `hakMenu()`) sendiri; klien tidak dipercaya. CORS `*` (tanpa cookie).

| Aksi | Metode | Siapa | Fungsi |
|---|---|---|---|
| `reset-password` | POST JSON `{user_id, password}` | Admin | Reset password akun peran **apa pun** kecuali akun sendiri (8-72 karakter) |
| `buat-akun` | POST JSON `{email, nama, role, password, kua_id?}` | Admin | Membuat akun; profil dibuat trigger `handle_new_user` lalu diperiksa (tidak sesuai = akun dibatalkan); `kua_id` wajib untuk Operator KUA |

File lama dibagikan "siapa saja dengan link", jadi diunduh lewat tautan unduhan publik Google Drive (mengikuti pengalihan; `resourcekey` ikut bila ada di tautan) dan isinya dicek dari byte awal (halaman HTML "akses ditolak" tidak pernah tersimpan). Maks. 20 MB. **Idempoten**: file yang sudah disalin ditandai `appProperties.lama = <ID file lama>` dan tidak digandakan. Tidak memakai scope di luar `drive.file`.

## 9. Konvensi dan pantangan
- **Jangan** menaruh rahasia (service role/secret key, Google client secret/refresh token, Turnstile secret) di berkas frontend, `apps-script/`, atau repo. `.env`, `akun.csv`, `username.csv` ada di `.gitignore`.
- Perubahan database harus **idempotent** (`create ... if not exists`, `create or replace`, `drop ... if exists`). Jangan `drop table` data aktif tanpa pengaman: konversi struktur lama memakai pola *ganti nama menjadi `_lama` -> salin -> verifikasi -> hapus*, dan **dibatalkan** bila ada data yang belum sama (lihat bagian 11).
- **Satu berkas per menu** di frontend dan satu berkas per modul di Apps Script; `bop.sql`, `bop/index.ts`, dan `bop.mjs` tetap satu berkas masing-masing: ubah langsung, jangan membuat file migrasi terpisah (upgrade database = jalankan ulang `bop.sql`).
- Kode lama yang dipindahkan dari proyek lain (`JX`, `BX`, mesin PDF Sertifikat, perhitungan kiblat) **disalin apa adanya**; tampilan dan penyimpanan dibuat terpisah. Ubah seperlunya, jangan menulis ulang tanpa alasan.
- Aturan baru ditulis di **server lebih dulu** (trigger SQL untuk BOP, `Bast.gs` untuk BAST), lalu cerminkan di UI (`calc()`, tombol) dan, bila menyangkut dokumen, di Edge Function.
- Hindari tabel log/audit dan cron (hemat kuota free plan). Jejak audit cukup `updated_by/at`, `submitted_*`, `verified_*`, `paid_at`; di Spreadsheet kolom `DiubahPada`.
- Zona waktu aturan = WIB (`Asia/Jakarta`). Pesan error berbahasa Indonesia dan menyebut angka (batas, terpakai, dimasukkan, kelebihan).
- Jangan menyimpan data turunan yang bisa dihitung (mis. `total` boleh karena dijaga trigger; azimut kiblat dan data matahari dihitung di klien tiap dokumen dibuat, bukan disimpan).
- Halaman yang memuat data async wajib memakai `ep`/`live(ep)` (lihat bagian 7); hasil `await` dari halaman lama tidak boleh menulis ke layar baru.
- Impor data lama membawa **hanya yang dipakai BIMASATU**. Jangan menambah bidang ke impor kecuali skema memakainya (akun/password lama, kuota API, ID, Total, metadata file, riwayat sengaja tidak dibawa).
- Setiap perubahan kode Apps Script butuh **Deploy > Manage deployments > Edit > New version** agar berlaku; frontend butuh `node bump-versi.mjs`; Edge Function butuh `npx supabase functions deploy bop --no-verify-jwt`.
- **Penulisan ke Google Drive hanya lewat Edge Function** (satu akun Google, satu folder master). Apps Script tidak menulis ke Drive (itu penyebab galat 403 sebelumnya); ia hanya mencatat id arsip dan, untuk arsip lama, membaca/membuangnya sampai dimigrasi.
- **Hak akses ditegakkan di server.** Menu atau aksi server baru wajib punya kunci menu (bagian 7) dan diperiksa di RLS/trigger (`can_menu`), Apps Script (`menu:`), atau Edge Function (`hakMenu`); menyembunyikan menu di tampilan saja tidak cukup.
- **Pemberitahuan lewat `jpToast`/`lapor()`** (lapisan paling depan, bagian 7); jangan membuat pop-up dengan `z-index` sendiri.

## 12. Batasan yang diketahui / ide lanjutan
- RPD masih bisa diturunkan di bawah Realisasi yang sudah masuk (belum ada penjagaan sebaliknya); admin belum bisa menghapus RPD.
- Realisasi SAKTI tidak terisi otomatis: petugas (Admin/Bendahara BOP) menginput nominal sebenarnya tiap bulan. Nominal itu **tidak dibatasi RPD** (sudah dibayar); batas RPD hanya berlaku saat Operator KUA mengirim Realisasi manual (total sebulan <= RPD bulan itu; per POS setahun <= RPD POS itu), dan operator terblokir selama ada kelebihan. Tidak ada batas per POS per bulan, dan tidak ada pemberitahuan otomatis ke operator yang terblokir: ia melihat banner saat membuka Realisasi.
- Pengaturan SAKTI global: tidak ada riwayat kapan sebuah KUA mulai SAKTI. Bulan lama yang sudah berisi Realisasi manual tidak diubah; satu sumber per POS per bulan dijaga di Realisasi SAKTI.
- Nominal yang dibayarkan admin tidak memengaruhi batas RPD/anggaran (hanya dicatat dan dibatasi <= total Realisasi). Baris `paid` lama (sebelum fitur ini) tampil "nominal belum dicatat" sampai admin mengisinya.
- Impor data lama: file LPJ diunduh lewat tautan publik Google Drive. Bila berbagi "siapa saja dengan link" di Drive lama sudah dicabut, berkas gagal (dilaporkan, baris datanya tetap masuk tanpa tautan). Salin berkas berurutan (±3 detik per berkas), halaman harus tetap terbuka; aman diulang.
- Laporan dibuat di browser (cukup untuk 31 KUA). File LPJ milik akun Google yang menjalankan `bop.mjs drive`; refresh token tidak berlaku bila app Google masih *Testing* (7 hari) atau izin dicabut.
- Plan Free Supabase: project dijeda setelah ~1 minggu tanpa aktivitas, tanpa backup otomatis.
- Apps Script: tiap panggilan 1 sampai 3 detik (jaringan + Spreadsheet); halaman BAST memuat semua data dalam satu panggilan (`bastInit`). Kuota harian akun Google (UrlFetch dan waktu eksekusi) cukup untuk beberapa admin, bukan untuk penggunaan massal.
- Perubahan peran, hak akses menu, atau pencabutan sesi baru berlaku di Apps Script setelah cache pemeriksaan login habis (maksimal 5 menit); peran dan menu dibaca lewat RPC `akses_saya`. Di tampilan, perubahan hak akses berlaku saat pengguna memuat ulang halaman atau login ulang (tidak ada dorongan waktu nyata); server (RLS, Edge Function) langsung memakai hak yang baru.
- Migrasi arsip BAST NR berjalan dari browser admin: berurutan (±6 detik per arsip), tab harus tetap terbuka, aman diulang. File lama tidak dihapus otomatis (pilihan "buang ke Sampah" hanya untuk yang berhasil disalin dan punya id file; arsip yang hanya punya tautan tidak dibuang). Arsip yang tautannya tidak lagi dibagikan "siapa saja yang memiliki link" gagal disalin dan harus diunggah ulang.
- Tarif Jaspro/Transport berlaku per peristiwa menurut tanggalnya (kolom Tanggal laporan, atau tanggal acuan bila kosong), bukan per bulan. Laporan lama tanpa kolom Tanggal memakai tanggal acuan untuk semua barisnya.
- Spreadsheet adalah satu-satunya salinan data Sertifikat dan BAST NR: aktifkan riwayat versi, buat salinan berkala (lihat PANDUAN-INSTALASI.md bagian Cadangan). Arsip BAST NR di Drive tidak ikut terhapus saat Berita Acara dihapus.
- Kolom `Nip`, tanggal, dan porporasi di Spreadsheet berformat teks; jangan mengubah formatnya atau menyunting angka panjang langsung di sheet.
- Logo kop PDF BAST NR membaca `assets/logo-kemenag.png` (opsional). Dokumen Sertifikat membawa logonya sendiri di kodenya.
- `assets/b-logo.png` (logo dan ikon website) **tidak ada di paket**: tambahkan sendiri. Tanpa berkas itu logo memakai ikon tautan bawaan dan tab memakai ikon bawaan peramban. Ikon tab diperbarui peramban paling lambat; tutup dan buka lagi tabnya setelah mengganti gambar.
- Penampil dokumen: kanvas tajam dibatasi 16 juta piksel dan 8192 px per sisi (batas iOS Safari), jadi pada halaman PDF yang sangat besar zoom ekstrem tetap dapat tampak sedikit lembut. Zoom maksimal 10 kali "pas lebar" (gambar: 3 piksel layar per piksel asli).

## 17. Backend Apps Script (`apps-script/`)
Satu proyek Apps Script **terikat** pada satu Spreadsheet (`SpreadsheetApp.getActiveSpreadsheet()`), dideploy sebagai Web App (**Execute as: Me, Who has access: Anyone**). Manifes `apps-script/appsscript.json` mengunci izin: `spreadsheets`, `drive` (hanya untuk membaca/membuang arsip BAST NR LAMA yang dulu diunggah akun ini, selama belum dimigrasi), `script.external_request` (Supabase). Panggilan Drive lewat REST (`UrlFetchApp` + `ScriptApp.getOAuthToken()`) tidak terdeteksi otomatis sebagai kebutuhan izin, jadi cakupan `drive` harus tertulis di manifes; tanpa itu arsip lama gagal dibaca dengan HTTP 403.
- **Konfigurasi di bagian paling atas `Code.gs`**: `SUPABASE_URL`, `SUPABASE_KEY` (publishable; sama dengan `js/config.js`). `DRIVE_MASTER_FOLDER_ID` sudah dihapus (penulisan Drive lewat Edge Function).
- **Protokol**: POST dengan `Content-Type: text/plain` (menghindari preflight CORS) berisi JSON `{ "action": "...", "token": "<access token Supabase>", ... }`. Jawaban `{ success: true, ... }` atau `{ success: false, code, message }`; `code`: `AUTH`, `FORBIDDEN`, `CONFIG`, `SUPABASE`, `BUSY`, `BAD_REQUEST`, `UNKNOWN_ACTION`, `ERROR`.
  `GET` mengembalikan JSON status (versi, `deployedActions`, apakah konfigurasi Supabase terisi): cara cepat memastikan deployment aktif.
- **Login dan izin**: `periksaToken_` membaca isi JWT (`sub`, `exp`; keabsahan diperiksa Supabase), lalu **satu** permintaan `POST /rest/v1/rpc/akses_saya` memakai token itu (jalur yang sama dengan website) yang mengembalikan `{id, nama, role, menus}`. 401 = sesi tidak sah (alasan Supabase ikut dilaporkan); 401 "Invalid API key" = `SUPABASE_KEY` salah (`CONFIG`); fungsi `akses_saya` belum ada = `CONFIG` ("jalankan bop.sql terbaru").
  Hasil di-cache sebesar sisa umur token (maks. 5 menit; kunci cache berawalan `sb2_`); token ditolak di-cache 60 detik. Lalu `izinkan_(aksi, user)`: aksi `admin: true` hanya untuk Admin; aksi bertanda `menu:` (satu kunci atau daftar, salah satu cukup) hanya untuk akun yang menunya memuat kunci itu (Admin selalu lolos); tanpa keduanya = semua akun yang login. Ditolak = `FORBIDDEN`.
- **Router**: `actions_()` menggabungkan aksi dasar (`Code.gs`) dengan `bastActions_()` (`Bast.gs`) bila ada. Aksi `write: true` dijalankan di bawah `LockService` (tunggu maks. 20 detik; lewat = `BUSY`).
- **Setup**: `setupDatabase()` (aman diulang) membuat/menambah sheet dan kolom tanpa mengubah data (termasuk kolom `ArsipMaster` di `BastBA`); `authorizeAccess()` memicu izin dan mencatat keterjangkauan Supabase, akun Drive yang dipakai Apps Script, dan cakupan izin pada token (periksa bahwa `drive` ada).
- **Deployment** tidak otomatis ikut kode: setiap perubahan butuh *Manage deployments > Edit > Version: New version*. Deployment lama tetap menjalankan versinya sendiri.
